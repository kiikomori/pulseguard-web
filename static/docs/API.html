PulseGuard watch API (v1)

Authentication: Authorization: Bearer <API key>. Each account has one API key, created on the API page (/api). Making a new key revokes the old one; the key is shown once and stored hashed. No cookies, so no CSRF token is needed.

Every request made with a valid key appears on the API page: time, endpoint, status, how many readings were saved, already received or rejected (with the reason), field names, device names and the time span. The raw body is not stored.

Base URL: https://<uw-site>/api/v1. All timestamps are ISO 8601; send UTC (Z) or an offset. Rate limit: 120 requests per hour per code (enough for one upload a minute plus catch-up).

GET /status

Checks the code and returns the server clock.


{ "ok": true, "server_time": "2026-11-04T18:05:00Z", "max_batch": 500 }

POST /readings (recommended, every few minutes)

Send one reading, a list, or { "readings": [...] } (max 500 per request).

FieldTypeRangeNotes
tsstring≤ 5 min in the future, ≤ 30 days oldrequired
bpmnumber20–250heart rate
spo2number50–100blood oxygen %
temp_cnumber30–45skin temperature °C
stepsnumber0–100000steps since the previous reading (a delta, not a daily total)
activitystringrest, light, moderate, vigorous, sleeplets PulseGuard skip high-heart-rate alerts during exercise
devicestring≤ 40 charsdefault watch

At least one of bpm, spo2, temp_c, steps is required. Unknown fields are rejected.


curl -X POST https://<uw-site>/api/v1/readings \
  -H "Authorization: Bearer $PULSEGUARD_KEY" -H "Content-Type: application/json" \
  -d '{"readings":[{"ts":"2026-11-04T18:00:00Z","bpm":72,"spo2":97,"temp_c":36.6,"steps":120,"activity":"light"}]}'

Response (200 when anything was accepted or already stored, 400 when everything was rejected):


{ "accepted": 1, "duplicates": 0, "rejected": 0, "errors": [], "alerts": 0 }
  • Idempotent: the same (device, ts) is stored once, so a watch can safely resend after a network error.
  • Alerts: readings from the last 6 hours are checked against the user's own limits; old backfill never raises alerts.
  • errors lists { "index", "error" } per rejected item, e.g. out_of_range_bpm, ts_in_future, unknown_fields.

POST /entries (Health Quest compatible)

Unchanged payload: date, time, steps, sleep, water, weight, bpm, notes. A bpm value is also stored as a reading.

Errors

401 invalid_api_key · 413 batch_too_large · 429 rate_limited · 400 invalid_json.

Nederlands (kort)

Stuur metingen met POST /api/v1/readings en uw API-sleutel (te maken op de API-pagina, /api) als Authorization: Bearer …. Eén meting, een lijst of {"readings": [...]}, maximaal 500 per keer. steps is het aantal stappen sinds de vorige meting. Dezelfde meting twee keer sturen is veilig. Meldingen ontstaan alleen voor metingen van de afgelopen 6 uur.
